### logicA-1 Clearing a setting brings back the Netlify variable
- Problem: with no stored row, resolveSettings uses the Netlify variable the setting replaced. Choosing Default or emptying a field saves null, which deletes or leaves out the row, so the variable keeps applying (sales stay open, an old price stays live, kits stay held, tax stays off). The page shows `row?.value ?? def.fallback` as "Now" and says the variables are "no longer read", so the admin can't see it.
- Evidence: settings-core.ts:146-152 `if (raw === undefined) { const fromEnv = env[def.env]?.trim(); ... }`; settings.ts:58-59 deletes the row on null; page.tsx:72 "Still set in Netlify and no longer read".
- Fix: show the effective value and source on the page and reword the notice; while a variable is set, store a clear as an explicit row. Operational workaround: save every setting on /admin/settings after deploy, then remove the variables from Netlify.
- Verifier: confirmed; Medium (only while leftover variables exist).
