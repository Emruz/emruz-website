### sens-1 Migration 028 hard-deletes every self-assessment
- Problem: `delete from assessments where framework = 'cis-v8'` removes every row with the column default. The base code never set `framework` (base assessments.ts:86, 279), so this covers every self-assessment since the feature shipped on main in 0d115b1 (2026-11-11): completed, in progress, partner-attributed and staff-assigned. The delete is irreversible, writes no audit row and bypasses the soft-delete column (007). Engagements keep their copied ratings (`on delete set null`, 005_workbench.sql:41) but lose the link. The migration comment says the rows "were pre-launch test data"; the repo cannot confirm that.
- Evidence: 028:7 `delete from assessments where framework = 'cis-v8';`; 004:20 `framework text not null default 'cis-v8'`.
- Fix: before deploy, run `select status, count(*) from assessments where framework = 'cis-v8' group by 1` in production. If any are real, change to `update assessments set deleted_at = now() where framework = 'cis-v8' and deleted_at is null`; at minimum, take a snapshot first.
- Verifier: confirmed, High. Whether the rows are test data has to be checked in production.

### logic-A1 Env values not carried into site_settings
- Problem: resolveSettings returns the default when a key has no stored row and no longer reads the environment. Migration 027 copies only the kits launch date. From deploy until an admin re-enters values on /admin/settings: a held `SKILLS_REF` is dropped and the newest release is served; an early `KITS_LIFETIME_UNTIL` reverts to 2027-12-31 and reopens the lifetime offer; `STRIPE_AUTOMATIC_TAX=false` turns back on; sales switches close; Motiv prices are null; lease, grace, seats and email addresses revert. docs/site-settings.md:33 lists re-entry as a manual step.
- Evidence: settings-core.ts:144 `if (raw === undefined) return def.fallback;`; 027:13-15 copies only `kits_launch_date`. Base read SKILLS_REF and KITS_LIFETIME_UNTIL from env (base admin/kits/page.tsx:27, config.ts:36).
- Fix: when a key has no stored row, read `process.env[def.env]` through checkSetting before the fallback, for one release; or seed site_settings before the new code goes live.
- Verifier: confirmed, Medium. edge-A3 and sens-3 merged into it.

### logic-A2 Multi-request uploads link the file to only the first request
- Problem: the upload route and clientAddLink store `evidence.request_id = requestIds[0]` but set every request in `requestIds` to received. getRequests counts evidence only by `e.request_id = r.id`, so the other requests show "Received" with "0 received". Requests with no erl_id get no link to the file at all, and "first" follows database order, not the user's.
- Evidence: route.ts:48 `const requestId = requestIds[0] ?? null;`; :67-70 loop sets every request received; workbench.ts:189 `(select count(*)::int from evidence e where e.request_id = r.id)`.
- Fix: store every request link (e.g. an evidence_request_links table) and count from it; or count evidence linked through the request's ERL item as well.
- Verifier: confirmed, Medium. logic-B2 and edge-B4 merged into it.
